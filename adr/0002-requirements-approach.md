# 2. Вибір формату специфікації вимог

**Status:** Accepted
**Context:** Потрібно обрати формат документування вимог, який підходить для подальшого тестування та усуває двозначність (згідно з лекцією Тема 6, §6.7.1).
**Decision:** Використовувати комбінацію EARS для загальних функціональних вимог та Gherkin (Given-When-Then) для деталізації конкретних Use Cases.
**Consequences:** 
* Формат Gherkin безпосередньо транслюється в E2E-тести. 
* EARS структурує вимоги, але вимагає уважності при синхронізації з кроками Gherkin.
